ABOUT RCAI: ROOT CAUSE ANALYSIS INTELLIGENCE

Evidence-Grounded Autonomous System Investigation, Verification, and Bounded Remediation

RCAI is an evidence-grounded autonomous investigation system designed to diagnose complex distributed microservice failures. Rather than relying on passive log summarization or static alert heuristics, RCAI actively investigates: it formulates competing root-cause hypotheses, calculates expected information gain to query targeted telemetry, cryptographically seals evidence provenance with SHA-256 signatures, gates remediation through deterministic safety policies, and empirically verifies recovery using post-action traffic probes.

01
Active Epistemic Search
Executes purposeful diagnostic tool calls based on information gain rather than dumping telemetry into an LLM context window.
02
Competing Hypotheses
Maintains 5 distinct fault families simultaneously, updating belief distributions as supporting and contradicting signals arrive.
03
Cryptographic Provenance
Every collected metric, log, and trace span is normalized and sealed with SHA-256 signatures for tamper-evident audit trails.
04
Bounded Safety Gates
The AI proposes actions, but a deterministic policy engine strictly authorizes them. Direct bash execution is strictly forbidden.
05
Empirical Outcome Proof
Remediation is only declared resolved after independent synthetic traffic probes verify error rates and latencies have normalized.
06
Scientific Benchmark Integrity
Evaluated across a 47-scenario frozen benchmark manifest with strict evaluator isolation preventing ground-truth leakage.
THE AUTONOMOUS INVESTIGATION LIFECYCLE

The formal 7-stage state machine governing evidence collection, verification, and controlled remediation.

STATE MACHINE
STAGE 1
DETECTED

Anomaly detectors capture elevated error rate, latency spike, or queue saturation.

STAGE 2
INVESTIGATING

Autonomous loop executes targeted telemetry queries within budget limit (15 tool calls max).

STAGE 3
HYPOTHESES EVALUATED

Belief scores across 5 fault candidate families update dynamically as evidence arrives.

STAGE 4
ROOT CAUSE VERIFIED

Leading hypothesis verified against confidence threshold (≥ 70%) and cryptographic audit.

STAGE 5
POLICY GATE

Deterministic policy engine validates service topology, idempotency, and action safety.

STAGE 6
REMEDIATION EXECUTED

Bounded corrective action applied (e.g. version rollback, index rebuild) with zero bash.

STAGE 7
OUTCOME RESOLVED

Synthetic traffic generator sends test probes to empirically verify telemetry normalization.

ROOT_CAUSE_UNKNOWN

When evidence is insufficient, contradictory, or ungrounded, RCAI performs safe refusal rather than fabricating an uncertain diagnosis.

POLICY BLOCKED

If remediation targets an unknown service, duplicate action, or forbidden command, the policy gate blocks execution and escalates safely.

HUMAN APPROVAL REQUIRED

High-risk infrastructure operations generate cryptographic approval tokens requiring explicit operator authorization before execution.

MATHEMATICS & ALGORITHMS BEHIND RCAI

Direct mathematical formulations and heuristic approximations implemented in the RCAI core engine.

ALGORITHMIC GROUNDING
1. Diagnostic Entropy & Uncertainty Routing agent/routing/selector.py:54
Uncertainty(H) = | p(H) - 0.5 |

Variables: p(H) ∈ [0.0, 1.0] is the confidence probability of hypothesis H.

Mechanism: Sorts active candidates by proximity to maximum binary entropy (p = 0.5). RCAI selects the diagnostic tool that provides maximum expected information gain to disambiguate the most uncertain candidate.

Classification: Heuristic Approximation of Shannon Information Gain.

2. Evidence Confidence Accumulation agent/hypothesis/models.py:38-51
Supporting: p_{t+1}(H) = min(1.0, p_t(H) + 0.20)
Contradicting: p_{t+1}(H) = max(0.0, p_t(H) - 0.25)

Variables: w_sup = 0.20, w_con = 0.25 (asymmetric contradiction penalty).

Mechanism: As normalized telemetry arrives from diagnostic collectors, evidence is mapped to categories. Contradicting signals penalize belief heavier than supporting signals to prevent false-positive lock-in.

Classification: Bounded Additive Belief Update with Asymmetric Penalty.

3. SHA-256 Telemetry Provenance Hash observability/normalizer.py:28
Signature = SHA-256( CanonicalJSON(src, collector, q, ts, data) )

Variables: Canonical JSON string containing telemetry source, collector identifier, query parameters, timestamp, and raw payload.

Mechanism: Guarantees immutable auditability. The Root Cause Verifier rejects any evidence record whose SHA-256 signature cannot be verified from the raw telemetry payload.

Classification: Cryptographic Hash Function (FIPS 180-4 Standard).

4. Root Cause Verification Decision Gate agent/verification/engine.py:42-67
Verified(H) ⟺ (p(H) ≥ 0.70) ∧ (|E_sup(H)| ≥ 1) ∧ (∀e: ValidSig(e))

Variables: E_sup(H) is the set of supporting evidence IDs for hypothesis H; ValidSig(e) validates SHA-256 provenance signature.

Mechanism: Diagnosis is verified if and only if confidence meets or exceeds threshold (0.70) AND at least one provenanced evidence record exists. Otherwise, RCAI demotes to ROOT_CAUSE_UNKNOWN.

Classification: Deterministic Multi-Criteria Verification Function.

BOUNDED AUTONOMY: AI PROPOSES, DETERMINISTIC POLICY ENFORCES

The strict boundary separating AI hypothesis generation from authorized infrastructure execution.

SAFETY ARCHITECTURE
WHAT THE AI INVESTIGATOR DOES
  • Formulates candidate hypotheses from anomaly symptoms
  • Calculates expected information gain for diagnostic selection
  • Executes read-only telemetry queries within budget limit
  • Proposes bounded remediation actions matching verified diagnosis
WHAT THE DETERMINISTIC POLICY ENFORCES
  • Topology Validation: Target service must exist in active 5-service topology
  • Zero Arbitrary Shell: Direct bash commands are strictly blocked (FORBIDDEN_COMMAND)
  • Idempotency Protection: Duplicate remediation executions are denied
  • Human Approval Gate: High-risk operations require explicit approval tokens

POST-ACTION EMPIRICAL OUTCOME VERIFICATION

Why execution success is never conflated with incident recovery.

CLOSED-LOOP PROOF

Conventional automated tools declare success the moment a script returns exit code 0. RCAI rejects this assumption. An action execution may succeed while the underlying service remains degraded (e.g. rollback succeeded, but database pool remained locked).

METRIC 1
Traffic Error Rate
Post-remediation error rate must normalize below ≤ 5.0%
METRIC 2
p95 Latency Threshold
Latency p95 must return within normal baseline window (< 80ms)
METRIC 3
Active Fault Flags
Simulated and injected fault counters must reach exactly 0
METRIC 4
Synthetic Traffic Probes
Dispatches 10 live synthetic HTTP probe requests to verify health
CURRENT SYSTEM LIMITATIONS

Honest engineering disclosures regarding the scope and boundaries of the RCAI system.

ENGINEERING DISCLOSURES
1. Route-Level Micro-Localization

RCAI localizes faults to the service and component level. Disambiguating sub-function line-level defects requires integration with continuous profiling tools.

2. Dynamic Causal Graph Learning

Currently operates over declared service topologies and dependency health collectors. Real-time online causal structure discovery via continuous DAG learning represents an ongoing research frontier.

3. Multi-Cloud Network Partitions

Evaluated in microservice clusters and OpenTelemetry testbeds. Cross-region BGP routing flap partitions require additional eBPF-level telemetry collectors.
